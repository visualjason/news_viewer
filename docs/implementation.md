## 已验证的参考站实现

通过公开 index.html、app.js、styles.css 及该期 JSON 分析：站点使用原生 DOM，没有前端框架或运行时打包依赖；首页读取 data/latest.json 和 data/archive/index.json，以 hashchange 切换历史 JSON。日期与 revision 共同构成期刊身份。它是已生成内容的展示层，生成模型、质量检查、采集覆盖等信息作为 JSON 元数据展示，不能据此推断其后台具体实现。

版式由顶部刊头、左侧 sticky 日期及分类目录、右侧阅读区组成。浅米色底、深绿强调色、衬线大标题、细分隔线形成纸质刊物感。850px 以下压缩侧栏，620px 以下隐藏侧栏。正文先展示总览和行动建议，再按行业、研究、开源、实践、教程分组。详情中保存技术分析、事实、限制、引用。阅读时长通过中文字符及英文词数估算。

交互包括历史面板、日期筛选、同日修订、上下期、最新一期、分类筛选、目录定位和原生 details 展开。原站还包含内部预览嵌入、运行报告、质量提示和按阅读预算选择展开分析等能力。

## 本仓库方案与已实现范围

保持纯静态架构，适用于当前空仓库及 GitHub Pages。独立编写界面与逻辑，参考信息结构和视觉方向。新增本期搜索，使用原创演示数据，不镜像原站新闻。

index.html 提供语义结构；styles.css 提供响应式刊物版式；app.js 管理归档、hash 路由、搜索分类与 DOM；lib.mjs 提供共享验证和筛选函数。data/archive/index.json 是前端索引，单期 JSON 按日期和修订保存。scripts/import.mjs 导入校验后更新目录，scripts/build.mjs 验证所有归档并输出 dist，scripts/serve.mjs 提供本地服务。

分类与搜索组合生效；类别目录只展示当前结果；未知类别归入其他资讯。加载失败保留当前已读内容并提示，找不到期刊允许从历史面板恢复；快速切换由请求代次防止旧响应覆盖新页面。使用 textContent 渲染用户文本，链接限制协议，归档路径按固定模板匹配。

不需要数据库或后端 API；所有内容通过静态 JSON 请求读取。后续采集系统只需按既有字段导出 JSON，再执行导入和提交。原站内部运行面板、模型生成、复杂审核报告不在本次阅读器范围中。

## 验证与上线

Node 测试覆盖危险链接、分类兼容、搜索组合、无效日期、重复 ID。构建验证目录路径及期刊身份。GitHub Actions 在 main 更新时执行测试、构建并部署 Pages。仓库管理员需选择 GitHub Actions 为 Pages 来源。

默认示例不是实际新闻；生产使用时替换为自己的已审核内容。无第三方依赖，无需 npm install。不要把 API key 放进公开 JSON 或静态代码。
